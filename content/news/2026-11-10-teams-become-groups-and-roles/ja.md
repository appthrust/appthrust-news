AppThrust のアクセス管理からチームがなくなり、グループとロールで管理するようになりました。Project にアクセスできるのは、その Project でロールを割り当てられたユーザーと、ロールを割り当てられたグループのメンバーです。

## 変わること

- **Project の「アクセス」タブ**: [Dashboard]({{.PlatformAPIURL}}) の Project の「設定」に「アクセス」タブが加わりました。ここでユーザーやグループに「管理者」「編集者」「閲覧者」のいずれかのロールを割り当てます。管理者はアクセスと設定を含むすべてを管理でき、編集者はリソースを作成・変更でき、閲覧者は閲覧だけができます。Project を作成した人は、その Project の管理者になります。
- **グループの作成**: グループは Dashboard の「設定」ページの「グループ」で作成します。メンバーを AppThrust で指定する Local と、ID プロバイダーの groups クレームでメンバーが決まる Claim の 2 種類があります。グループは、ロールを割り当てるまで何も付与しません。
- **グループの再マッピング**: ID プロバイダーのグループに対応付けた Claim のグループは、「再マッピング」で新しいクレーム値に付け替えられます。新しいグループを作ってすべてのロールの割り当てを移し、そのあとで元のグループを削除するので、付け替えの途中でグループが外れるロールの割り当てはありません。
- **apth**: Project へのアクセスはロールの割り当てで決まるため、Platform のコマンドに `--team` や環境変数 `APTH_TEAM` を指定するとエラーになります。

## 必要な対応

- **Project の管理者**: 「アクセス」タブで、必要なユーザーとグループに適切なロールがあるかを確認してください。足りない場合は「アクセスを追加」を選び、ロールと、「ユーザー」か「グループ」を選んで、「編集者として追加」のようにロール名の付いたボタンで追加します。
- **グループを作る人**: グループの作成には、プラットフォームロールの「グループ管理者」か「プラットフォーム管理者」が必要です。
- **メンバー**: 見えるはずの Project が見えない場合は、その Project の管理者に「アクセス」タブで追加してもらってください。apth のスクリプトで `--team` や `APTH_TEAM` を指定している場合は外してください。

## 注意点

- 「アクセス」タブを確認・変更できるのは、その Project の管理者だけです。Project には常に 1 人以上の管理者が必要です。
- ロールの割り当てを外すと、次のリクエストから反映されます。グループのメンバーの変更は、ユーザーのアクセストークンが更新された時点で反映されるため、すぐに反映したいときはサインインし直してもらってください。
- 再マッピングで変えられるのはクレーム値だけで、発行元は変わりません。元のグループは削除され、新しい名前のグループに置き換わります。
