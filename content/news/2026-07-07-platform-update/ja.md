今回のアップデートに含まれる主な変更をお知らせします。

## クラスターと運用

- **接続経路の状態**: [Dashboard]({{.PlatformAPIURL}}) に Runtime Path Health ページを追加しました。ワークロードまでの接続経路を層ごとに確認でき、問題のある層と次に必要な対応を表示します。Project の概要と公開 URL のカードにも状態を表示します。
- **Runtime Sets**: ワークロードクラスターのまとまりごとに、稼働状況と更新の進み具合を確認できるページを追加しました。Kubernetes / Talos のバージョン更新では入れ替え用のクラスターを先に準備し、必要な確認が通るまでは現在のクラスターで処理を続けます。影響と監査理由を確認してから、切り替えやロールバックを実行できます。
- **ストレージ容量の状況**: Storage ページとクラスターのストレージ画面に、容量のリスクと、AppThrust が自動で対応中か承認待ちか、次に必要な操作を表示するようになりました。ストレージを縮小する計画は、縮小後の容量やデータ保護の状況を確認してから承認できます。

## Project

- **仮想マシン**: Project の Platform メニューに Virtual Machines を追加しました。VM イメージを取り込んで仮想マシンを作成し、起動、停止、再起動、バックアップ、復元を操作できます。
- **DNS レコードの表示**: Domains タブで、ゾーン内のレコードを、自分で追加したものとコンポーネントの公開時に自動で作られたものに分けて表示し、それぞれの反映状態を確認できるようになりました。Platform API からゾーンへのレコードの追加と削除もできます。
- **アプリケーション作成時の Observability**: アプリケーションの作成画面で Observability を有効にし、準備済みのプロバイダーを選んで、メトリクス、ログ、ダッシュボード、アラートを接続できるようになりました。

## プラットフォームサービス

- **Platform Services（ベータ版）**: Git ホスティング、コンテナレジストリ、Observability をプラットフォームサービスとして作成するページをベータ版として追加しました。配置先を選び、計画を確認してから作成します。作成後は詳細と診断の画面で、依存先の準備状況を確認できます。

## Platform API

- **scale-to-zero の状態**: コンポーネントとコンテナインスタンスのリリース状態に、scale-to-zero の状態（無効、稼働中、ゼロまで縮小済み、不明）と、実際のレプリカ数・目標のレプリカ数を含めるようになりました。

## 修正

- GitHub App のインストールから Dashboard に戻ったとき、インストール先が保存されず、ソース接続の作成に進めない問題を修正しました。Project の設定と Integrations からも接続一覧を開けます。
- ソースリポジトリにイメージ取得用の認証情報を追加しても、そのリポジトリを使う既存のアプリケーションスタックに反映されず、非公開レジストリのイメージを取得できない問題を修正しました。
- アプリケーションスタックの作成時に指定した配置先のクラスターとデータベースの設定が、各コンポーネントに反映されない問題を修正しました。
- アプリケーションスタックから作成したコンポーネントのリリース状態を取得できない問題を修正しました。
