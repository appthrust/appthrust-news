データベースのスキーマやデータを管理する開発者向けに、PostgreSQL のデータベースを変える SQL を「変更」として提出できるようになりました。変更はレビューと必要な承認を経て適用され、結果は変更履歴に残ります。

## できること

- SQL を画面で書くか、Flux のソースとして登録された Git リポジトリの SQL ファイルから読み込めます。
- 提出前に「レビューのプレビュー」で文の数とリスクを確認でき、DROP や DELETE などを含むと警告が出ます。
- DROP TABLE や TRUNCATE を含む変更は、既定では 1 件の承認が必要です。
- `apth databases changes` でも、作成、承認、実行などができます。

## 使い方

1. [Dashboard]({{.PlatformAPIURL}}) のサイドバーの「データベース」で対象を選び、「変更」タブで「新しい変更」を押します。
2. 「ソース」で「インライン SQL」か「Flux Git ファイル」を選び、SQL を入力するか、ファイルを選んでプレビューします。
3. 「適用モード」を選んで「変更を作成」を押します。初期値の「自動」はレビューと承認が済むとすぐに、「手動」は詳細画面で「実行」を押すと適用されます。
4. 承認が必要な変更は、詳細画面で「承認」か「却下」を選びます。

## 注意点

- MySQL には対応していません。分離ランタイムの Project では、Neon のデータベースにも使えません。
- WHERE のない DELETE や UPDATE、DROP DATABASE、DROP SCHEMA を含む変更はレビューで止まり、実行されません。
- 作成後に SQL は編集できません。直すときは新しい変更を作ります。
- 「適用モード」の初期値は「自動」です。適用の前に内容を確かめたいときは、「手動」を選んでから作成してください。
- apth は [GitHub の appthrust/cli](https://github.com/appthrust/cli) から入手できます。
